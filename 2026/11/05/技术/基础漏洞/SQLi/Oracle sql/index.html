关于Oracle sql 与Mysql 的不同之处

MySQL & Oracle 手工 SQL 注入 整合完整版手册

适用：PortSwigger 靶场、CTF 手工注入

Payload 全部为原始文本，直接粘贴进 Burp Repeater 参数 value 框，不用手动 URL 编码

核心原理两者完全一致：用户可控输入直接拼接进 SQL 字符串，未使用预编译，导致注入

预编译局限：只能防护 WHERE 条件里的值；ORDER BY/GROUP BY 这类 SQL 结构拼接，预编译无效，只能白名单

一、系统元数据映射（最重要！）

功能 MySQL Oracle 备注
查询所有表 information_schema.tables all_tables / user_tables user_tables只看当前用户自己的表，注入优先用；all_tables能看当前用户有权限访问的所有表；dba_tables需要 DBA 权限
查询所有列 information_schema.columns all_tab_columns / user_tab_columns 视图里的字段名都叫table_name、column_name，只是存放位置不同
筛选当前库 /schema table_schema=database() owner=USER MySQL 叫数据库；Oracle 叫 Schema (用户)

记忆口诀：

MySQL：查表、列都在information_schema里面

Oracle：没有information_schema，用user_tables/user_tab_columns（优先）

二、基础语法 & 注入常用函数对比

![[Pasted image 20261015210139.png|700]]

关键名词解释

  1. dual：Oracle 虚拟伪表，只有一行空数据。Oracle 语法强制 SELECT 必须带 FROM，查常量、函数结果没有真实表时，用FROM dual占位。
  2. ROWNUM：Oracle 伪列，不是表真实字段。查询输出结果之后，按顺序给每行分配编号，从 1 开始。只能直接用ROWNUM=1获取第一条。
  3. LISTAGG：Oracle 聚合函数，把多条查询结果合并为一行字符串，自定义分隔符。靶场表少的时候，一次性爆出全部表 / 列。超过 4000 字符失效，改用ROWNUM+NOT IN逐行获取。

五、防御方案（MySQL、Oracle 通用）

  1. 首选：参数化预编译 PreparedStatement

    防护 WHERE 子句参数值注入

    无法防御 ORDER BY、GROUP BY 这类 SQL 结构拼接，结构类只能白名单

  2. 最小权限原则：数据库账号只分配业务必需权限，不要 DBA 管理员权限

  3. 输入校验：白名单 > 黑名单，黑名单容易绕过

  4. 禁用危险函数 / 包

    • MySQL：限制secure_file_priv，禁止into outfile写文件
    • Oracle：配置 ACL，禁用utl_inaddr、utl_http

  5. 转义函数仅作为辅助防护，存在宽字节注入等绕过方式，不能单独防御注入

  6. WAF 属于辅助防护，存在大量绕过手段，不能单独依赖

六、高频坑点汇总

Oracle 坑

  1. 常量查询必须写FROM dual，直接SELECT 'xxx'语法报错
  2. ROWNUM=2直接查询永远为空；listagg 超长报错才用ROWNUM+NOT IN循环爆数据
  3. UNION 列类型必须严格匹配，不确定就用 null 占位
  4. 表名字典内大写，匹配时引号内必须大写
  5. 注释不能用#，只能-- 或者/* */
  6. 不支持堆叠注入，分号;不能执行第二条 SQL
  7. 优先使用user_tables/user_tab_columns，减少无关数据干扰

MySQL 坑

  1. GROUP_CONCAT有长度上限，过长会截断
  2. ||不是字符串拼接，要用CONCAT()
  3. LIMIT m,n：跳过 m 行，取 n 行

七、最简实操顺序（PortSwigger Oracle Lab）

  1. ORDER BY 判断列数
  2. Gifts' UNION SELECT 'test123',null FROM dual -- 验证 UNION 注入
  3. listagg 一次性拿全部表名
  4. listagg 拿目标表全部列名
  5. UNION SELECT 列 1, 列 2 FROM 目标表 WHERE ROWNUM=1 – 读取账号密码
