32

只要输入'，PHP 就会**自动加反斜杠转义变成 \'**，直接写1'会变成1\'，单引号失效，没法闭合。

数据库连接编码是 GBK，GBK 是双字节编码，两个字节算 1 个汉字。

绕过原理（重点）

你传：%df%27（URL 编码：%df + 单引号%27）

  1. PHP 收到，看到'，给它加反斜杠：%df%5c%27
  2. MySQL 以 GBK 解析：%df%5c 拼成一个合法 GBK 汉字，吃掉这个\
  3. 剩下单独的%27也就是**单引号’**，成功逃逸，用来闭合 SQL。

一句话：%df或%aa吃掉 PHP 自动添加的反斜杠，释放出单引号。

payload:
?id=0%df%27%20union%20select%201,2,group_concat(password)%20from%20users%20–+

Less32 使用手写自定义函数，通过多轮正则替换转义\、'、"，不处理空字节\0；Less33 直接使用 PHP 原生addslashes()，可同时转义\、'、"、\0。二者均为 PHP 层面的字符转义，在 MySQL 使用 GBK 字符集的场景下，都可以被宽字节注入%df%27绕过。

38

堆叠注入：
审计源码时，判断是否存在堆叠注入，优先查找数据库执行函数：

  1. 若使用mysqli_multi_query()，代表支持一次执行多条 SQL，存在堆叠注入的底层条件；
  2. 检查用户输入是否直接字符串拼接进 SQL，若无过滤 / 预编译，则漏洞可利用；
  3. 配套出现mysqli_more_results()、mysqli_next_result()，是处理多条 SQL 结果集的配套函数，进一步佐证多语句执行能力。

可以在第二条语句执行增删改，也可以查但是没有回显

核心两点：

  1. 前面关卡：数据库连接写在外部文件 sql-connections/sql-connect.php，用include引入，连接变量写在别的文件，本页面看不到。

php

连接代码在外部文件，所以当前页面源码看不到mysql_connect。

  1. Less38 把数据库连接代码直接写在当前 php 文件内部，不再引入外部连接文件，并且选用mysqli扩展 + mysqli_multi_query做多语句堆叠查询。

靶场作者这么设计的原因（CTF 报告直接写）

  1. 为了演示mysqli_multi_query的完整使用流程

    mysqli_multi_query、mysqli_more_results、mysqli_next_result 全都**依赖 mysqli 的连接句柄$con1**。

    作者直接把 mysqli 连接写在当前页面，方便你一次性看完整套完整代码：

    建立连接 → 拼接可控 id → multi_query 执行多条 SQL → 判断多结果集。

    如果继续用外部 include，你还要去翻另一个文件看 mysqli 连接，不方便学习。

  2. 区分两套数据库 API：老 mysql 扩展 vs mysqli 扩展

    前面宽字节关卡用的是废弃的mysql_*函数，写在外部公共连接文件。

    38 是新知识点「堆叠注入」，专门切换到mysqli这套 API，直接在本页面写连接代码，清晰展示 mysqli 整套调用，用来教学。

  3. 设计考察点：

    考察审计的时候，能认出mysqli_multi_query，理解它依赖 mysqli 连接，支持分号多条 SQL。
